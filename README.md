# 守护连线：授权式远程协助原型

这是一个可直接打开的前端交互原型，用来演示安全远程协助的用户流程：

- 被协助者输入一次性 6 位连接码并主动发起请求
- 协助者看到明确的授权弹窗，可以拒绝或同意
- 屏幕共享、鼠标键盘、文件传输分别列出，默认最小权限
- 任意一方都可以结束连接，连接码在会话结束后失效

打开 `index.html` 即可体验。当前版本只演示浏览器内的授权流程和状态变化，不会连接到真实电脑，也不会绕过操作系统权限。

## 安装成 App

用本地静态服务器打开（Service Worker 需要 `http://localhost` 或 HTTPS）：

```bash
python -m http.server 8080
```

然后访问 `http://localhost:8080`。在 Chrome 或 Edge 地址栏右侧选择“安装守护连线”，即可添加到桌面/开始菜单。`manifest.webmanifest`、`sw.js` 和 `icon.svg` 已包含在目录中。

## 做成可用产品时的建议架构

1. 使用 WebRTC 传输屏幕流和输入事件，信令服务只负责交换会话信息。
2. 每个连接码只允许使用一次，并设置很短的过期时间；服务端保存哈希而不是明文验证码。
3. 由被控端原生客户端调用系统屏幕捕获与输入注入 API，并在系统托盘持续显示“正在共享/控制”。
4. 所有输入事件、权限变更和断开操作写入本地审计日志；文件传输单独确认。
5. 身份认证使用设备密钥或短期令牌，传输使用 DTLS-SRTP / TLS，禁止静默启动和后台驻留。

## 互联网连接实验

`connect.html` 和 `server.js` 提供一个最小的 WebRTC 屏幕共享实验：

```bash
npm install
npm start
```

在服务器的 `8787` 端口访问页面；被控端生成 6 位码，协助端输入后，被控端点击“同意并开始共享屏幕”。当前只共享屏幕，不注入鼠标键盘。示例使用公共 STUN，生产环境还需要 HTTPS、身份认证、短期令牌和 TURN 中继服务，否则部分网络环境无法直连。
